# Campus production pilot setup

The repository includes two Render configurations. The root `render.yaml` is a free presentation demo with no database, Gemini key, or real sign-in. This guide describes the paid, database-backed setup in `render.production.yaml`: PostgreSQL with pgvector and one Node service that runs the web app and document worker together. A persistent disk keeps private PDF uploads available to both processes.

## Before creating the Blueprint

1. In Render, create a new Blueprint from `pidamarthidhanushhh/one_camp` on the `main` branch and select `render.production.yaml` as the Blueprint file. Review the selected service and database plans before approving creation. The `campus-pilot` service name must be unique in your Render workspace; if you rename it, the callback URL will use the assigned Render hostname.
2. The initial app starts in sign-in setup mode. It does not expose demo credentials while `OIDC_ISSUER` is configured. The Google sign-in button remains unavailable until the client is added.
3. After Render assigns the service URL, create a **Web application** OAuth client in Google Cloud Console. Set its authorized redirect URI to:

   ```text
   https://<your-render-service-host>/auth/callback
   ```

   The app derives the callback from Render's `RENDER_EXTERNAL_URL`; a custom `OIDC_REDIRECT_URI` is not required.
4. In the Render web service's Environment settings, add `OIDC_CLIENT_ID` and `OIDC_CLIENT_SECRET` as secrets. Set `OIDC_SETUP_PENDING` to `false`, then redeploy. Never commit or paste the client secret into source files or chat.
5. Keep `OIDC_ALLOWED_EMAIL_DOMAINS=matrusri.edu.in` if only verified Matrusri accounts should sign in. Change it only to the institution's actual email domain(s). Add faculty and administrator addresses in `CAMPUS_FACULTY_EMAILS` and `CAMPUS_ADMIN_EMAILS`; all other permitted first-time users receive the student role.
6. Add `GEMINI_API_KEY` in Render to enable PDF analysis and Raze. Without it, login and non-AI pages can run, while AI endpoints return a clear unavailable response.

Keep `CAMPUS_ORGANIZATION_ID` stable after the first successful migration. Changing it later would make existing users' memberships and documents belong to a different organization.

Database migrations run automatically before each deploy. `SESSION_SECRET` is generated by Render. The database and app use Singapore to keep their private-network connection in one region. The app requests TLS for PostgreSQL; Render's internal database certificate is self-signed, so the Blueprint enables TLS without certificate verification for that private connection.

## Scope and operating limits

- The managed PostgreSQL schema stores identities, roles, sessions, uploaded-document metadata, and Raze study artifacts. First-time OIDC login creates a student account automatically.
- The web service and worker share one persistent disk, so the pilot is intentionally a single-instance setup. Move files to private object storage before scaling to multiple app instances.
- Saved resources, Crates, planner data, ratings, announcements, and other prototype state still use browser storage. They will not sync across devices or users until those features are migrated to server APIs and database tables.
- Configure a verified college domain and approved OAuth consent screen before inviting real users. The app sends PDF text to Gemini when document indexing is enabled; get the institution's approval for that data processing before enabling uploads for real course material.
- Before inviting users, replace demo/sample resources with authorized content and publish the applicable privacy, retention, and acceptable-use notices.

## Cost shape

The Blueprint selects Render's `1c-2g` web plan, `0.1c-256mb` PostgreSQL plan, and 1 GB persistent disk. Current listed prices are about $25/month, $6/month, and $0.25/month respectively, before workspace, bandwidth, storage growth, and Gemini usage. Confirm current pricing in Render before approving service creation. Free Postgres is temporary and unsuitable for retaining pilot account data.
